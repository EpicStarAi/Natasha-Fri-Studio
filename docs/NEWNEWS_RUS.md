# NEW🌏NEWS🇷🇺RUS — запуск редакционной студии

Русскоязычная редакция на базе Natasha-Fri-Studio. По умолчанию: мировые новости;
фокус переключается на «Россия и мир» или «Технологии и AI» в редакторе.

## Что реализовано

- Главная `/`: сценарий, до 6 тем, источники для каждой темы, план до 60 секунд,
  схема композиции и имена медиафайлов; адаптивная светлая/тёмная тема.
- Автосохранение незавершённого черновика в браузере; экспорт JSON без API и ключей.
- Серверное сохранение JSON с Bearer-ключом, уникальными ID, постоянным каталогом
  и проверкой входных данных. Это хранилище производственных пакетов, не очередь GPU.
- Локальный FFmpeg-монтаж: заставка 1 секунда, готовые клипы ведущей с озвучкой,
  фото/видео темы сверху, ведущая снизу. Без иллюстрации — ведущая на весь кадр.
- Выход: MP4 H.264/AAC, 1080×1920, 30 fps, без субтитров и дополнительной музыки.
- Старый интерфейс доступен по `/legacy`. Его новости, подписки и показатели —
  данные прежнего демонстрационного прототипа, не реальные материалы нового канала.

Студия **не генерирует** lip-sync или голос, не проверяет содержание URL, не
запускает ночное производство и не публикует в соцсети. Подключение реального
AI_FACTORY и аккаунтов — следующий этап. Индикатор «API подключён» означает
доступность API; он не означает готовность GPU, моделей или социальных аккаунтов.

## Быстрый запуск без PostgreSQL

Требования: Node.js 24, pnpm 11, Python 3.10+, FFmpeg/FFprobe для монтажа.

```bash
pnpm install --frozen-lockfile
pnpm run build
```

Первый терминал:

```bash
# Значение остаётся только на вашей машине; не добавляйте его в Git.
export NEWNEWS_STUDIO_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
export NEWNEWS_DATA_DIR="$PWD/data/newnews"
export ENABLE_LEMLIST=false
pnpm --filter @workspace/api-server start
```

Второй терминал:

```bash
pnpm --filter @workspace/natasha-fri dev
```

Открыть `http://localhost:5173`. Vite проксирует `/api` на `127.0.0.1:5000`;
для другого API используйте `API_PROXY_TARGET`.
При необходимости просмотра только с этой машины: `pnpm --filter @workspace/natasha-fri exec vite --host 127.0.0.1`.

Редактор и экспорт работают без `NEWNEWS_STUDIO_TOKEN`. Ключ включает серверное
сохранение: введите его в разделе «Производство». Он хранится только в памяти
страницы, не попадает в localStorage и пакет. При отсутствии ключа или длине
меньше 32 символов API сохранения возвращает 503.

`DATABASE_URL` нужен только при `ENABLE_LEMLIST=true`. Включение старого Lemlist
требует отдельного аудита доступа к его маршрутам. Для новой студии он выключен.

Для постоянной установки подходит существующий `compose.web.yml`: API получил
том `newsroom_data`. После заполнения `.env`:

```bash
docker compose -f compose.web.yml up -d --build
```

Compose сохраняет прежний PostgreSQL-сервис ради совместимости. Запуск Docker
на целевом ПК и автозапуск Windows/WSL этой доработкой не выполнялись.

## Один выпуск от сценария до MP4

1. В «Выпуске» задайте название, темы, текст ведущей и примерную длительность.
2. В «Источниках» добавьте хотя бы одну HTTPS-ссылку к каждой теме. Проверьте
   дату события, факты, имена, цифры и права использования иллюстраций.
3. В «Производстве» укажите имена файлов. Пример структуры:

```text
media/
  intro.png
  presenter-1.mp4
  broll-1.mp4
  presenter-2.mp4
  broll-2.jpg
```

4. Подготовьте голос и lip-sync **с утверждённой ведущей NEW NEWS**. В проект не
   добавлена новая случайная ведущая. В каждом `presenter-*.mp4` должны быть видео
   и финальная озвучка; фото не принимается вместо говорящей ведущей.
5. Скачайте пакет, например `episode.json`, и проверьте материалы:

```bash
python3 scripts/render_newnews.py episode.json --assets media --check
python3 scripts/render_newnews.py episode.json --assets media --output renders/episode.mp4
```

Плановые секунды не обрезают клипы. Монтаж использует **фактическую полную
длительность** видео/озвучки и добавляет секунду заставки. Если получается больше
60 секунд, сборка остановится: сократите текст и пересоздайте клип. Большое
расхождение длительностей аудио и видео также блокирует сборку. Это проверка
технической целостности, не автоматическая оценка ударений или качества lip-sync.

Изображения: PNG/JPEG/WebP. Видеоклипы: MP4/MOV/WebM/MKV. Имена файлов:
латинские буквы, цифры, дефис, подчёркивание, точка; без папок, URL и пробелов.
Все файлы должны лежать непосредственно в `--assets`. Внешние симлинки не
принимаются. FFmpeg не скачивает материалы. Готовый файл не перезаписывается.

Исходные кадры вписываются с сохранением пропорций, с полями при необходимости;
автоматической обрезки головы/рук нет. Иллюстрация занимает верхние 720 px,
ведущая — нижние 1200 px. Графика канала должна присутствовать в подготовленных
материалах; монтаж не добавляет логотип и не рисует субтитры поверх лица.

Перед публикацией просмотрите MP4: постоянство лица, волосы, зубы/губы,
артефакты рук, ударения, окончания фраз, соответствие иллюстраций источнику.
Публикация в этой версии выполняется отдельно.

## API для локального n8n / AI_FACTORY

Основной контракт: `lib/api-zod/src/newsroom.ts`. Новые маршруты описаны в
`lib/api-spec/newsroom.openapi.yaml`; старые сгенерированные API-хуки не изменены.

| Метод | Маршрут | Действие |
|---|---|---|
| GET | `/api/newsroom/status` | Профиль и состояние настройки сохранения; без секретов |
| POST | `/api/newsroom/packages` | Проверить черновик и записать JSON на диск; Bearer обязателен |
| GET | `/api/newsroom/packages/{id}` | Прочитать пакет по UUID; Bearer обязателен |

POST принимает `title`, `focus`, `introAsset`, `scenes`. У темы: `id`, `headline`,
`narration`, `sourceUrls`, `durationSeconds`, `presenterAsset`, `brollAsset`.
Сервер сам назначает канал, UUID, формат и `state=awaiting_media`.
`publication.automatic=false`; добавленные клиентом настройки публикации игнорируются.

Каталог пакетов хранится постоянно; создавайте резервные копии. Сохраняются только
метаданные/сценарии, не видео. После рендера JSON остаётся `awaiting_media`:
автоматического обновления статуса, воркера и списка выпусков пока нет.
Скрипт выводит JSON-отчёт `rendered` с путём и фактической длительностью.

## Проверки

```bash
pnpm run build
pnpm run test:newnews
```

Тесты проверяют формат/источники, авторизацию, запрет подмены канала и публикации,
сохранение/чтение, независимые конкурентные записи, отсутствие требования БД,
выход за папку медиа, отсутствие звука, превышение времени и реальную сборку
тестового MP4 через FFmpeg с заставкой, иллюстрацией и полноэкранным клипом.

## Что необходимо для запуска самого канала

1. Привязать утверждённые портрет/голос и конкретный работающий local lip-sync
   workflow AI_FACTORY. Проверить его на RTX 5060 8 GB коротким реальным выпуском.
2. Подключить список источников, сбор новостей, дедупликацию, русский сценарий
   и сохранение ссылок. Текущие старые n8n workflow не следует считать проверенными:
   основной `natasha-workflow.json` делает фон с голосом, использует общие временные
   пути, а некоторые workflow содержат старые назначения/профили.
3. Создать/выбрать отдельные аккаунты NEW🌏NEWS🇷🇺RUS в нужных соцсетях и Telegram,
   настроить авторизацию и возврат реальных ID опубликованных материалов.
4. После контрольного видео подключить новый изолированный workflow и автозапуск.
   Существующий NEWNEWS_OPEN_V1 и его расписание эта ветка не меняет.
