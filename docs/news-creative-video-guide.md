## 1. Типовой процесс «новостного креатива» (каркас гайда)

```
новость (RSS / Telegram)
  → отбор и фактчек
  → сценарий, разбитый по сценам (hook → 3–5 фактов → CTA)
  → кадры: генерация изображения на каждую сцену
  → анимация кадров (image-to-video, 3–5 сек на сцену)
  → озвучка (TTS)
  → субтитры (форс-капшены)
  → монтаж: склейка сцен + голос + музыка
  → проверка (ручной аппрув)
  → публикация (Shorts / TikTok / Reels)
```

Что уже известно про стек автора: озвучка — **ElevenLabs**, сборка —
**After Effects** (ручной монтаж). Важное отличие нашего подхода: у
автора монтаж ручной, у нас — автоматический (ffmpeg в n8n), поэтому
процесс автора мы воспроизводим не «в лоб», а как конвейер.

| Этап | Нода(ы) | Реализация |

## 3. Чего не хватает (разрыв с процессом «новостных креативов»)

| # | Пробел | Комментарий |
|---|---|---|
| 1 | **Сценарий не разбит на сцены** | нужен JSON `{scenes:[{voiceover, image_prompt, duration}]}` вместо сплошного текста — без этого нечем управлять кадрами |
| 2 | **Нет генерации кадров** | сейчас один статичный фон; нужен image-gen (DALL·E/Flux/Midjourney-API) на каждую сцену |
| 3 | **Нет анимации кадров** | image-to-video (Kling/Hailuo/Runway/Veo) — опционально, можно начать с Ken-Burns-зума в ffmpeg (`zoompan`) |
| 4 | **Нет субтитров** | форс-капшены дают основную досматриваемость; Whisper → SRT → `ffmpeg -vf subtitles=` |
| 5 | **Нет музыки/SFX** | фоновая подложка + duck под голос (`sidechaincompress` или просто `volume`) |
| 6 | **Аппрув не блокирует публикацию** | `Send Review` шлёт видео, но публикация не ждёт ответа; нужен wait-on-webhook или инлайн-кнопки Telegram (`EPICGRAM_AI_DRAFT_APPROVAL` как основа) |
| 7 | **Нет фактчека новости** | для новостного формата обязателен шаг «проверь источник, убери непроверяемое» в промпте Claude |
| 8 | **Публикация не через дистрибьютор** | `natasha-workflow.json` публикует сам; правильнее слать в `EPICSTAR_CENTRAL_DISTRIBUTOR` |
| 9 | **Нет AI-ведущей** | у автора в кадре «актёр»-ведущий (новостная студия, липсинк под озвучку ElevenLabs); у нас голос звучит поверх фона. Опциональный этап: talking-head-аватар НАТАШИ (HeyGen/Hedra/липсинк-модель) как первая/последняя сцена |

## 3.1 Стратегия: два бренда — два формата

Решение (11.08.2026): форматы разделяются по брендам, а не наслаиваются
в одном конвейере.

| Бренд | Формат | Конвейер | Площадки |
|---|---|---|---|
| **ИНТЕРНЕТ БЕЗ ОГРАНИЧЕНИЙ** | текстовые карточки: инсайт → мануал → послевкусие | `IBO_VIDEO_PIPELINE` + `scripts/render_ibo.py` (готово) | Telegram-канал, далее кросспостинг |
| **NATASHA \| FREE RUS** | AI-ведущая в кадре (формат PIRATE CPA): фотореалистичный диктор с липсинком + новостные вставки | `natasha-workflow.json` (модернизация: вместо статичного фона — аватар-сцена) | сеть аккаунтов NATASHA: YouTube Shorts / TikTok / Reels (публикация уже реализована в workflow) |

Архитектура формата NATASHA: новость → Claude (сценарий ведущей) →
ElevenLabs (голос) → сервис аватара/липсинка (HeyGen / Hedra / Higgsfield:
портрет «Наташи» + голос → говорящая ведущая) → ffmpeg (ведущая как
хук-сцена + карточки фактов) → YouTube/TikTok/IG. Нужен один
дополнительный API-ключ; ориентир стоимости — $0.1–1 за ролик.
Константа бренда: единый портрет-референс Наташи для консистентности
ведущей между роликами.

## 4. Целевой workflow «NATASHA News Creative»

```
RSS / Telegram (новость)
  → Dedup (static data, как в EPICSTAR_RSS_CONTENT_ENGINE)
  → Claude: сценарий по сценам (JSON)
       { title, caption, scenes: [ { voiceover, image_prompt, duration } ] }
  → Split In Batches по scenes:
       → Image Gen (кадр 1080×1920, единый стиль-пресет NATASHA)
       → [опц.] Image-to-Video 3–5 сек | иначе ffmpeg zoompan
  → ElevenLabs: озвучка полного текста (склейка voiceover всех сцен)
  → Whisper → SRT
  → ffmpeg: concat сцен → + голос + музыка (duck) → burn-in субтитры
       → 1080×1920, libx264, faststart
  → Telegram-аппрув с инлайн-кнопками ✅/❌ (блокирующий, wait-on-webhook)
  → POST /webhook/epicstar-publish (EPICSTAR_CENTRAL_DISTRIBUTOR)
  → Analytics → отчёт в Telegram
```

Ключевые изменения промпта сценариста (нода `Generate Script`):

- перевод на Claude (`ANTHROPIC_API_KEY` уже есть в стеке);
- ответ строго JSON по схеме сцен, 4–6 сцен по 3–5 сек;
- правило фактчека: «используй только факты из переданной новости,
  ничего не додумывай, спорное опускай»;
- в `image_prompt` — единый стиль-префикс канала (задать константой
  `NATASHA_STYLE_PROMPT`), чтобы кадры были в одном визуальном стиле.

Новые переменные окружения (добавить в `.env.example` при реализации):

```
IMAGE_GEN_API_KEY=          # ключ image-gen провайдера
IMAGE_GEN_MODEL=            # модель кадров
VIDEO_GEN_API_KEY=          # опционально: image-to-video
NATASHA_STYLE_PROMPT=       # стиль-префикс кадров
NATASHA_BGM_FILE=           # фоновая музыка (mp3 в /home/node/assets)
WHISPER_API_KEY=            # субтитры (или локальный whisper.cpp)
```

Порядок внедрения (каждый шаг даёт рабочий конвейер):

1. Сценарий по сценам (JSON) + фактчек — правка одной ноды.
2. Кадры image-gen + ffmpeg `zoompan` вместо статичного фона.
3. Субтитры Whisper → burn-in.
4. Блокирующий Telegram-аппрув.
5. Музыка + публикация через центральный дистрибьютор.
6. (Опционально) image-to-video вместо zoompan.

## 5. Что нужно из расшифровки ролика

Чтобы превратить «типовой каркас» в точное воспроизведение процесса автора,
из расшифровки (или самого видеофайла) нужно:

1. Список инструментов по шагам (генерация кадров, анимация, монтаж).
2. Тексты/структура промптов автора для сценария и кадров.
3. Параметры: длительность сцен, соотношение кадров, стиль субтитров.
4. Любые приёмы отбора новостей (источники, критерии «залётности»).
