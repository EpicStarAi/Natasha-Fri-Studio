# Журнал производства NEW NEWS

Для каждой папки задания автоматически создаются `production.events.jsonl` и
`production.events.run.json`. Второй файл хранит общий UUID задания. Озвучка,
InfiniteTalk и монтаж используют один журнал, если выходные файлы лежат в одной
папке. Для других папок передайте одинаковый `--run-log /path/to/production.events.jsonl`
в `synthesize_avatar_voice.py`, `capture_infinitetalk.py` и `render_newnews.py`.

Каждая строка JSONL — отдельное событие: UTC-время, runId, PID процесса, этап,
результат и детали. Начало/успех/ошибка сохраняются сразу с fsync. Ошибка содержит
тип, сообщение, traceback и длительность этапа. Для готовых файлов сохраняются
размер и SHA-256. Записи дописываются; повторный запуск не стирает предыдущий сбой.

## Какие этапы записываются

| Этап | Диагностика |
|---|---|
| voice.validate / voice.model_load / voice.synthesis | Проверка входа, загрузка модели, синтез, голос/язык/скорость |
| presenter.generate / presenter.input | Подготовка ведущей, контрольные суммы изображения, WAV и workflow |
| comfy.queue / comfy.wait / comfy.result | promptId, seed, исходное разрешение, heartbeat каждые 30 секунд, сообщения ComfyUI |
| media.validate | Наличие материалов, формат, таймкоды, длительности |
| intro.render / scene.N.windows / scene.N.cue | Заставка, монтаж темы и расписание каждого окна |
| montage.concat / audio.normalize | Склейка, измерение и нормализация звука |
| output.verify / output.save / output.file | Размер кадра, длительность, атомарное сохранение, SHA-256 MP4 |

Встроенный просмотр журнала:

```bash
python3 scripts/production_log.py /path/to/project/production.events.jsonl
```

Он выводит последнее состояние каждого этапа, историю ошибок и повреждённые
строки. `started` без последующего результата означает незавершённый этап:
проверить процесс, heartbeat и исходный лог. Это не доказательство зависания;
журнал сам не перезапускает процессы и не является круглосуточным watchdog.
Если процесс принудительно завершён или пропало питание, событие `failed` может
не успеть записаться. Не заменять такую запись выдуманным успехом.

## Как исправлять точечно

- Ошибка материала или таймкода: исправить `episode.json` / файл, выполнить `--check`,
  затем повторить монтаж с новым именем MP4. Готовые голос и ведущая используются повторно.
- Ошибка монтажа или громкости: повторить монтаж; GPU-генерация для этого не нужна.
- Ошибка InfiniteTalk: найти `promptId` и сведения об узле в `.job.json` / `comfy.log`.
  При таймауте сначала проверить очередь: задание могло продолжить работу.
  Автоматически отправлять дубликат или прерывать чужую очередь нельзя.
- Ошибка текста / произношения: пересоздать WAV и соответствующую ведущую;
  границы окон сверить с новой фактической речью.

Логи сохраняются с исходниками выпуска. Для нового выпуска — новая папка и новый
runId; при исправлении того же выпуска — тот же журнал. Сводка показывает последний
результат этапа, а `failures` сохраняет и ошибки перед успешным повтором.

Ключи, cookie, окружение и полный текст сценария специально не собираются.
Известные формы секретов маскируются дополнительно. Сырые сторонние логи ComfyUI
могут содержать дополнительные данные; перед отправкой наружу их надо просмотреть.

## Подключение к уже запущенному выпуску Hera

Журнал подключён во время генерации. Существующие WAV, сценарий, мастер и таймкоды
отмечены `inputs.recovered` / `observedExisting`; это наблюдение готовых файлов,
а не восстановленные задним числом события синтеза. Наблюдатель связал текущий
promptId с `comfy.log` и `.job.json`. Последующие монтаж, звук и проверка пишутся
непосредственно во время выполнения. Следующие CLI-запуски начинают журнал с начала.

Этот журнал покрывает перечисленные производственные команды. Старые отдельные
n8n-процессы и внешние сервисы не объявляются подключёнными автоматически.
